## Objective and Validation Metrics

This session states the objective and criteria for phase 3’s prototype.

### Objective
This test aims to discover if the tutorial session can assist users to understand each functionalities, and finish the finial challenge without additional instructions. In addition, another purpose for this test is to identify whether the current tutorial sessions are intuitive and simple for users to go though, and allow them to understand how each functionalities can be performed correctly.

### Criteria
1.  Users can get through each tutorial within 3 min. Success/Fail.

2.  Users face minor or no struggles during each tutorial session. Rate 5 - 0 if the user experienced 0 to 5+ struggle situations.

3.  Users can perform the final challenge with minor or without any problem towards technical issues. Rate 5 - 0 if the user experienced 0 to 5+ problems.

4.  Users believe that tutorials are helpful in understanding various functions. Rates based on the user rating on the questionnaire.

### Qualitative Result
The list below showcase feedback from each tester among the testing process.

1.  **Tutorial 1/Shape Creation**

    - All of the tester can understand the guidance, and perform the shape creation within certain time.

2.  **Tutorial 2/Shape Scaling**

    - Tester 1 want to have more information on the indicator, for example add an arrow that points to the specific button, or write a hint like ‘B TO UNIFORM’ to tell the user which button on the controller is the correct one.

    - Most of the tester can understand the guidance in a short period of time, and make 1 mistake on average.

3.  **Tutorial 3/Gravity Control**

    - 3 users did not fully understand the guidance.

    - 2 users thought the description was too much in this tutorial.

    - Tester 2 did not finish this tutorial due to the misunderstanding of the content.

4.  **Overall Impression/Suggestions**

    - Tester 1 suggested to have a more obvious indicator for specific buttons

    - Tester 2 hoped to have different color indicators on gravity status for object, for example shadows and shape highlights.

    - Tester 3 was troubled by those bugs, he did expect a hot fix upon.

    - Tester 4 expected less word and more visual guidance for each tutorial

    - Tutor expect to have a current shape duplicate function, add visual navigation between each tutorial, expect the label to appear one by one instead of popping up entirely by once.

## Analysis and Evaluation Aims
According to the data collected, an overall analysis with a evaluation from 0 - 5 will be provided based on the criteria stated above.

1.  **Tutorial 1/Shape Creation**

    No issues have raised for any testers during this tutorial session.

    According to the criteria, the rating for tutorial 1 is ‘**Success, 5, 5, 5**’ .

    A clear navigation is needed in the future update, so that users will not get lost during the transmission between tutorials.

2.  **Tutorial 2/Shape Scaling**

    Tester 2 has gone through trouble in understanding the relation between uniform and non-uniform scaling, realized after my verbal explanation. A few tester stated that there are too many texts based guidance to read.

    The rating for tutorial 2 is ‘**Success, 4, 4, 5**’.

    It’s better to have a more obvious indicator in terms of using different colors, different state highlighter which can better indicates the current status.

3.  **Tutorial 3/Shape**

    Most of the user did not fully understand the guidance and known bugs due to overwhelming text content, and the lack of stage or step based tutorial make it impossible for user to determine if they have completed the tutorial. Tester 2 even skipped this tutorial.

    The rating for tutorial 3 is ‘**Success, 3, 5, 5**’ .

    It’s necessary to have a stage based tutorial similar to the previous tutorial, and it’s better to fix existing bugs.

4.  **Reflection and Suggestions**

    According to the final ‘overall experience rating’, users’ comprehensive experience is 4/5 in average. Which means I have reached the demanded score stated in the test plan. However, minor issues still exist among the whole testing period, and corresponding suggestions were provided by the questionnaire.

    It’s obvious that ‘tutorial’ is helpful for letting user better understand the correct way to use various functions. And instead of reading text, users expect to have more visual feedback like ‘stage changing’, ‘layer based switching’ and more ‘visual indicator’, indicates that users are more willing to accept intuitive visual displays than overwhelming text.

    Therefore, the testing aim and hypothesis of iteration 3 were successfully validated.

## Final Reflection
Overall, this testing session has provide me a deeper understanding and insight of creating an interactive based project.

My testing objective for IP2 is to verify if the user could understand each functionality with minor text based constructions. Obviously, this hypothesis and testing aim were falsified by the test results of IP2 and 3.

Therefore I can conclude that, a visual and stage based tutorial is necessary for user to understand new features, no matter how intuitive and easy the design looks. Designers must assume that users will get stuck at any step and setup corresponding assistance to solve the problem, or set restrictions to reduce the probability of user’s incorrect operation.

### Prototype Session Review
Both testing session for IP 2 and 3 have been chosen for this part, since their hypothesis and testing objectives can be mutually validated.

The hypothesis for IP2 is, ‘**users can perform each task successfully with little or no guidance successfully**.’, and the testing objective is to define whether ‘**user’s mental model fits with my conceptual model**’.

Obviously, this hypothesis is falsified by testing results and reflections. Most of the user couldn’t fully understand how to perform each functionality correctly, and therefore spent more time to explore through trial and error.

Accordingly, hypothesis for IP3 has changed into ‘**users can understand each functionality after finishing the corresponding tutorial** ’, the testing objective iterated to ‘ **whether tutorials can help user better understand each functionality** ’. Eventually, IP3’s hypothesis and testing aim have been validated through the result, all of the user believed that **these tutorials could help them better understand those tasks**.

### Methodological Reflection
Based on the characteristics of testing aims and functionalities, I choose to time on each task that each user has spent during the testing period, and use questionnaire to collect their thought and suggestions after doing the test. Quantitative and qualitative data will be collected respectively, allows for comprehensive analysis towards problems, suggestions and improvements. ‘Think aloud’ method was used at IP1 to collect participant’s thoughts during the task. However, I observed that verbalizing their thoughts often caused participants to pause their actions, which partially affected the result of time-on-task measurement. This data collection method was therefore excluded from the subsequent test after careful considerations.

### Concept Evaluation
My initial project concept was to build an immersive and intuitive XR environment for 3D modeling, at the purpose of solving pain points for traditional modeling environment. This concept was partially validated among the whole iteration. Specifically, the integration of the XR environment addressed the limitations users faced when viewing models on a 2D screen. It also enhanced users’ sense of immersion through ‘grab’ and ‘poke’ interactions, while the stage based tutorial helped lower the learning cost for beginners in 3D modeling.

### Improvements and Extensions

Eventually, the final concept has iterated to ‘define a visual based interactive XR environment for 3D modeling, accompanied with clear and comprehensible tutorials’. During the iterative process, the emphasis on the term ‘immersive’ was gradually reduced. Instead, the focus shifted toward building more accessible and ‘intuitive’ models, aiming to reduce users’ cognitive load and enable them to gain more information with less output.
